Security infrastructure case study

Wazuh Homelab

This project documents a learning-oriented SIEM deployment instead of just naming tools. The current public scope is a Wazuh Indexer on one Ubuntu VM and a Wazuh Dashboard on a second Ubuntu VM, both inside VMware Workstation, both wired with TLS, and both written up step-by-step. It is not a finished SOC stack yet, and the case study says that plainly.

Repository Indexer guide Dashboard guide
2 VMs Dedicated Ubuntu 24.04.4 LTS machines for indexer and dashboard.
192.168.71.100 Static IP assigned to the Wazuh Indexer on the VMware NAT network.
192.168.71.103 Static IP assigned to the Wazuh Dashboard with browser access over HTTPS.
TLS + tuning Certificate workflow, memory locking, JVM sizing, and service verification are all documented.

Project summary

Problem
Build a usable SIEM lab that exposes the configuration work, not just the tool names.
What I built
A single-node Wazuh Indexer VM plus a separate Wazuh Dashboard VM, both configured on Ubuntu Server 24.04.4 LTS in VMware Workstation.
Evidence
Public deployment guides, VM sizing, port requirements, TLS generation steps, verification commands, and correction notes in the repo.
What's complete
Indexer deployment, dashboard deployment, certificate regeneration, and documented verification of active services and accessible dashboard login.
What's next
Graylog ingestion, a proper server/manager layer, and a less fragile design than the current single-node indexer setup.

What makes this credible

It records mistakes and corrections.

The dashboard node was missing from the original certificate config, which forced a full certificate regeneration pass.

It documents verification, not just install commands.

The repo includes cluster initialization checks, service status validation, and the expected dashboard warning state when the server layer is missing.

It is explicit about what is incomplete.

No Graylog yet, no manager/server yet, and no high-availability cluster. Those are limitations, not hidden details.

Configuration artifact

This excerpt reflects the values documented in the public deployment guides for the single-node indexer setup and dashboard connection.

# Wazuh Indexer
network.host: 192.168.71.100
node.name: wazuh-indexer
cluster.initial_master_nodes: ["wazuh-indexer"]
bootstrap.memory_lock: true

# JVM sizing
-Xms4g
-Xmx4g

# Wazuh Dashboard
server.host: 192.168.71.103
opensearch.hosts: ["https://wazuh-indexer:9200"]
server.ssl.certificate: /etc/wazuh-dashboard/certs/wazuh-dashboard.pem
server.ssl.key: /etc/wazuh-dashboard/certs/wazuh-dashboard-key.pem

The repo also notes a CN mismatch correction in `opensearch.yml`, which is one of the reasons this reads as real work rather than polished summary copy.

Verification steps captured in the repo

Check What was verified
Cluster init `indexer-security-init.sh` completed and the log reported `Node has been initialized`.
Service state `systemctl status wazuh-indexer` and `systemctl start wazuh-dashboard` are both part of the written verification flow.
Browser access The dashboard guide records access to `https://192.168.71.103` and the expected login page.
Expected limitation The dashboard shows a no-server warning because the server/manager layer is not deployed yet.

Plain limitations

  • Single-node indexer means no high availability and no resilience if that VM goes down.
  • Graylog is planned but not deployed, so the broader event pipeline is still incomplete.
  • The dashboard warning about no connected server is expected, but it also means the current setup stops short of a full Wazuh workflow.
  • The public repo does not yet contain populated screenshots or architecture PNGs, so this case study relies on the written deployment evidence.

Why this still matters for hiring review

The strongest signal here is not scale. It is that the repo records infrastructure decisions, operational corrections, and verification steps in enough detail that another person could audit what was done. That is a better signal for an early-career security candidate than a page full of tool names.
